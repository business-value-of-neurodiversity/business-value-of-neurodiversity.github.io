# Editor guide (no coding needed)

1. Go to **`<site address>/admin/`** (ask the site's developer for the exact address).
2. Click **Sign in with GitHub** (or the access-token option if that is what you were given).
3. On the left, choose what you want to change:
   - **Site-wide pages** → Home page (logo, mission, audience), Resources, About Us
   - **<year> · Page content** → that edition's Event details, Home page, Schedule, Sponsors, Organizers page text, Host organizations
   - **<year> · Speakers** → click a name to edit, or **New Speaker** to add one
   - **<year> · Organizers** → same as speakers

   Each workshop edition (2026, 2027, …) has its own set. Make sure you are editing the right year.
4. Edit the fields and press **Save**. The site updates itself in about 1–2 minutes.

## Common tasks

**Change the date, time, price or registration link** → *<year> · Page content* → *Event details*.

**Publish a new edition** → *<year> · Page content* → *Event details* → set **Status** to `published` once the content is ready. While it says `planned`, visitors see a "details coming soon" banner. (A developer creates the blank edition first.)

**Add a speaker**
Speakers → *New Speaker*. Fill in name, job title, photo, biography. For *Session heading*, copy the text
exactly from another speaker in the same session (speakers with identical text are grouped under one heading).
Use *Display order* to control the sequence (1 first).

**Move a session or change a time** → *<year> · Page content* → *Schedule* → open the item and edit. Drag items to reorder.
Use "Break / meal bar" as the *Item kind* for the black break bars.

**Add a sponsor** → *<year> · Page content* → *Sponsors* → choose a tier → *Add sponsor* → upload the logo.
Please always fill in the **Name**: it is read aloud by screen readers.

**Replace a photo** → open the person → click the photo → upload or pick another image.
Tip: square-ish headshots, under about 1 MB, look best.

## Good practice
- Write short, plain sentences. Put the key information first.
- Every logo/photo needs a name (it becomes the image description for blind and low-vision visitors).
- Check the live site after you save. If something looks wrong, tell the developer: every change can be undone.
- You can't break the page design from the CMS. If you need something the form doesn't offer (a new section, a video), ask a developer.

**After a forum has happened** → *<year> · Page content* → *Event details* → set **Status** to `past`.
It moves from "Upcoming" into the **Past Events** menu, and the next planned forum takes the featured spot on the home page.
